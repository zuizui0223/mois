## 取得効率の原応答による実証

Esriの [getSamples API](https://developers.arcgis.com/rest/services-reference/enterprise/get-samples/) は複数の座標を一度に要求できるが、従来のindividual \`identify\` と数値・年/月・雲なし観測数が一致することが前提。

- [12点の検証 run 42320588365](https://github.com/zuizui0223/mois/actions/runs/42320588365)：VIIRS Jan/Jul放射輝度24/24、雲なし観測数24/24、人口12/12が原identifyとの表示精度内で一致。初回の監査スクリプトでVIIRSバンドをスペース区切りとして認識していなかったため **誤って0/12と報告したが**、保存した原バイトを独立再解析して一致を確認。
- [128点の検証 run 42321056750](https://github.com/zuizui0223/mois/actions/runs/42321056750) SUCCESS：**640数値／512雲なし観測数／512年月属性**をすべて元の原応答で検証。5回のAPI要求で従来640点×月等の個別応答と一致。初回run 42320926527の正規表現 \`[,\\s]\` のエスケープ誤りは検証失敗として停止、修正後に成功。
- [512点の検証 run 42321175353](https://github.com/zuizui0223/mois/actions/runs/42321175353) SUCCESS：**2,560の原数値＋2,048の雲なし観測数**と元のidentifyが一致。VIIRS 4か月は各512点を一括要求できた。WorldPopは512点でHTTP 414（URL長）となり、128点×4回に分割して正常終了。よって**成功したAPI要求8回（+停止した大きすぎる要求1回）**で、2,560の個別値を再現。WorldPopで一括512点を許容するとは主張しない。

この改善は**API要求数**の減少であり、サーバ応答時間や全球のフルジョブ速度が320倍になったという実測ではない。年・サービス・地域による挙動変化は今後も検証する。

現時点で本物の新64点取得を実施したコードは \`scripts/analysis/mois_global_multipoint_numeric_20261107.py\`。VIIRSのバンドは \`[raw radiance, cloud-free observation count]\` として扱い、出典の年・月、locationId、元座標を各点で検査する。WorldPopは単一人口ラスタバンド、年2020を要求するが**応答値に年が再掲されない**。NoDataは0に置換せず、雲なし観測数2未満はLOW_CLOUD_COUNTとし、3か月以上の有効VIIRSがない対象は完了にしない。取得値は原応答SHA付で保存し、オフライン再計算がバイト一致。
