# MOIS 220写真の観察ID正規化と花注釈（2026-11-14）

## 訂正：220写真は220独立観察ではない

従来のQC表にはUUID110件と数値観察ID110件が混在していた。数値110件を公式APIで取得し、同じ観察のUUIDへ正規化すると、**9組・18写真**が同じ観察に属した。したがって元写真220件を全て保持したまま、独立観察単位は**211件、分類群は96件のまま**となる。未照会のUUID101件は元ソースのUUIDを保持し、公式APIで最新記録を確認済みとは区別する。

前文書の「観察UUID220件、重複0」「独立観察220件」は誤りだった。文字列IDの一意性だけではID表記の異なる同じ観察を除外できない。

9分類群：Pueraria tuberosa、Phyllarthron arenicola、Iris almaatensis、Stillingia trapezoidea、Synedrellopsis grisebachii、Trigonella anguina、Ormosia paraensis、Droogmansia pteropus、Colchicum dregei。例えばIris almaatensisのphoto 59092775と59092784は同一観察37292560であり、別々の独立反復ではない。

## 花注釈と直接画像判定を分離

公式APIから取得した110観察はすべて、controlled-term辞書の `Flowers and Fruits / Flowers` 注釈を持つ。元QC表の119写真・90分類群に対応し、写真IDの所属と分類群IDは119行全て一致した。これは**90分類群に花ありの注釈付き観察が存在する**という記録上の証拠であり、個々の119写真に開花花弁が写っていることを検証した結果ではない。

この情報から、未分類を一律に「開花写真がない」と扱うことはできない。一方、今回の数値ID標本は無作為な全球標本ではなく、注釈割合を96分類群全体や未分類2,200分類群全体へ外挿しない。

直接の写真内開花判定は**0件完了**、新規数値ROI9成功も**0件**。画像ページへのアクセスが成立しておらず、元画像の再取得・再推定は行っていない。photo_flower_stageは全行unreviewedのまま。96分類群のうち残る6分類群を「花なし」とも判定しない。

## API失敗と再照会なしの復旧

[取得run 43593568216](https://github.com/zuizui0223/mois/actions/runs/43593568216)は数値IDの5バッチ・110観察とcontrolled termsの保存後、UUIDを整数専用のv1詳細ルートへ渡したためHTTP422で停止した。取得済み6JSONは[artifact 14113167546](https://github.com/zuizui0223/mois/actions/runs/43593568216/artifacts/14113167546)に保持。失敗を生物学的欠測に読み替えず、取得済みデータだけで同定対応を再計算する。

復旧コードはiNaturalist APIを呼ばず、署名固定した2ZIPを読むだけ。公式取得済み110観察の同定情報と元のUUIDを併用し、211観察の代表写真表・220写真全表・9組の別名ID差分・花注釈対応表を出力する。これは**全211観察のAPI再照合成功ではない**。
