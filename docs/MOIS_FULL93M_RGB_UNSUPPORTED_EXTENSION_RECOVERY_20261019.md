# MOIS: recover full 93,209,351-photo source first original-RGB wave (19 Oct 2026)

## Research owner decision and current state

**Primary current goal: increase actually processed original photographic colour outcomes.** Native/introduced-WCVP range tests, UV/pollinator joins, environmental model refits and manuscript hypothesis changes are all later steps. The complete observation/photo metadata index has **already succeeded**: [93,209,351 ID source release](https://github.com/zuizui0223/mois/releases/tag/mois-full-93209351-indexed-photo-observation-source-v1), containing 128 exact source photo shards, 128 observation shards and 16 SHA256-certified tar archives. [Source index run](https://github.com/zuizui0223/mois/actions/runs/39202507921) succeeded; source IDs alone have no measured colours.

The previous [first genuine RGB run #39227363353](https://github.com/zuizui0223/mois/actions/runs/39227363353) **failed at queue creation, not the model or photo download**. All sixteen source archives, full official 42,111-taxon counts and 350,399 already measured RGB photo IDs validated and downloaded correctly. The source scanner encountered an original `image_extension` outside the original pinned FCP loader's strict `jpg|jpeg|png` URL whitelist. An all-or-nothing `require(image_extension in {jpg,jpeg,png})` stopped the WHOLE sample. No original RGB attempts from the 93m holdout were completed in that failed run.

## Implemented source recovery and no artificial colour

- The full 93,209,351 candidate PHOTO-ID and OBSERVATION universe remains unchanged. Selection is original **observation-ID hash threshold p=0.0002**, no genus/taxon cap. All unselected records stay available at higher probabilities; all already acquired photo IDs remain skipped without re-downloading.
- For each pre-colour selected new photo: an original extension `jpg`, `jpeg` or `png` (with harmless case/leading-dot/whitespace variations) is normalized to the exact allowed FCP original URL format.
- Any unsupported source format (e.g. `gif`, `webp`, blank or malformed), instead of being guessed as JPEG or crashing the entire processing queue, is retained in an original source-only **`unsupported_selected_original_photo_formats.jsonl`** ledger containing its photo/observation/taxon IDs and verbatim original extension. No RGB pixels, colour labels or bloom status are assigned. These photo IDs remain included in the full source-frame and original hash selection denominator.
- New queue arithmetic must satisfy exactly **selected original photos = reused previously measured photo IDs + supported new photo measurements planned + unsupported selected original photo formats**. Unsupported counts by original extension and sidecar SHA256 are frozen in the manifest. Photo-ID sets between supported and unsupported paths must be disjoint.
- The unchanged original SHA-pinned FCP YOLO11 + EfficientSAM ROI-v4 loader/model handles only supported photo source formats, with prior provider rate limits, permanent source HTTP 404 terminal failures and image quality failures retained. We do **not** silently override the frozen loader to fetch formats it explicitly rejects.
- The new workflow runs on main-branch push of the queue/workflow files as well as the previous completed-index/workflow_dispatch gate. After a passing PR merges, the already-complete 93m source index can therefore trigger a genuinely **new** RGB pipeline without asking the user to manually click Run workflow.
- One 256-photo unit is a compute batch, **not a cap on the full index**. Source pre-colour sample p=0.0002 is a bounded first milestone; a future larger p can include previously unselected source observations without redrawing the hashes. No claim that the 93m source photo pixels were measured.

## Executable verification and outcome status

`tests/test_mois_full_index_observation_queue.py` verifies exact original-ID source conservation, deduplication, genuine supported JPEG case handling, unsupported-photos source-only ledger, record-by-record normalisation and technical unknowns left unmeasured. `.github/workflows/mois-full-index-incremental-RGB.yml` must publish `mois-full93m-observation-baseline-original-RGB-p0002-v1` **only after every original source measurement batch succeeds**. The expected source image provider may refuse or lack selected URLs: do not substitute another image's pixels or reselect favourable photos.

A completed RGB outcome requires an actual photo-level Parquet with `attempted`, `classifiable`, `image_acquisition_failed`, `unclassifiable_acquired`, frozen model signature, original source identity and SHA. At the time this protocol is written the recovery code is not evidence of new image pixel measurements. **All remaining native/island ecological analyses must wait while this acquisition goal is in progress.**
