## 操作手順

1. 上記の配布済みsource roster 128行からSHA固定した評価者A/BのHTMLを入手。別の植物学的評価者が**それぞれ独立**に用いる。どちらも元写真ID以外の地域・季節・自動花BOXステータスを画面には出さない。
2. 各写真の元URLは「手動で開く」リンクのみ。**HTMLが勝手に写真を取得・送信することはない。** 対応する写真を閲覧者がローカルに保存してHTMLに読み込み、写真IDの一致を本人が目視確認する（ファイルSHAだけでは真正写真を証明できない）。
3. 開花中の花、実際の花被（petal/tepal）、隣接背景の3項目にそれぞれ「はい/いいえ/不明」を記録。**3項目すべて「はい」の場合だけ**、同一写真の花被3点と隣接する自然背景3点をクリックして測定する。
4. 各クリックで5×5画素の各RGBチャンネル中央値、3点のチャンネル中央値を採用。IEC sRGB/D65からCIELAB変換し、CIE 1976 ΔE76、符号付きΔL*、sRGB相対輝度比を計算する。ファイルbytesのSHAとピクセル位置・RGB値もCSVに記録するが、**原画像bytesは保存・アップロードされない**。
5. 評価者A/Bは別々のCSVをブラウザからローカル保存し、研究調整者が独立データを回収して、公開リポジトリに**人手の原回答・座標・個別写真結果を投稿せず**、ローカルで `python -m scripts.analysis.mois_petal_background_contrast_review_v1 validate-private --roster <frozen_roster.csv> --reviewer-a A.csv --reviewer-b B.csv --output private_qc` とする。同一photo/obs/taxon IDの全128行・異なる評価者・一致する実画像SHA・一致する開花花被の判断・双方3+3点・RGBからの色差再計算を強制する。不一致・一方の不明・画像bytes不一致は欠測/要裁定に残し、**色差をゼロや白花に変換しない**。

写真閲覧・手動点選択には原ソース画像が必要なため評価者個人によるファイル保存は必要だが、GitHub Actionsのこのワークフローは元写真を1枚も要求しない。`file://` でWebCryptoが利用できないブラウザの場合は、HTTPローカルサーバー（Python `python -m http.server 8000`）でHTMLを表示する。外部公開サーバーは不要。

## 測定対象と解釈の境界

- 主出力は**個々の画像における非校正RGB由来の花被−背景の視覚的差**であって、送粉者の色覚やUV反射率、色素コスト、系統進化適応ではない。
- 書き込み対象は新しい**人手可視色差系列**のみ。元のoriginal strict9、技術unknown、500px BOX Lab、既存の写真・観察ID、MOIS×Island文献の種形質値を書き換えない。
- 測定可能な128写真は**ROI9が失敗した画像から、YOLO陰性・大型BOX等を意図的に選んだ**。大陸・島・北極・南半球や世界野生在来植物相の「地味な花率」をこれから直接推定してはいけない。
- 単一写真の局所背景は同じ花の自然生育環境の代表でない場合があり、露出・ホワイトバランス・圧縮・画像形式・選んだ点・撮影機材も未補正。複数花や異なる背景を持つ写真は備考へ明示する。
- 128写真の植物学的二重確認・数値一致結果が揃った**後**、実際の形質と文献の `green_brown_inconspicuous`・小花・繁殖様式を連結し、定義を混ぜず検証する。未実施段階で生態学的な定量効果を宣言しない。
